# 시험 카드와 인물 선택 영수증

같은 인물에게 같은 질문을 다시 물으려면 안내문과 판단 근거의 판도 함께 남겨야 합니다. 시험 카드는 그 조건을 한 JSON 파일에 담습니다. 실제 지원 자격이나 여론을 판정하는 서식은 아닙니다.

## 시험 카드 v1

[스키마](../engine/scenarios/schema-v1.json)는 JSON Schema 2020-12 형식입니다. [예시 카드](../engine/scenarios/examples/offline-help-v1.json)는 실제 인물·제도·시행일을 사용하지 않는 가상 자료이며, 검사 결과가 항상 ‘판정 보류’가 되도록 표시했습니다. 예시의 uuid와 revision도 가짜 값이므로 실제 데이터에서 조회할 수 없습니다.

| 항목 | 남기는 내용 |
|---|---|
| `schema_version`, `scenario_id` | 규격 판(`"1"`)과 시험 식별자입니다. |
| `persona_uuid`, `source_revision` | 인물 uuid와 원본 데이터의 40자리 커밋 SHA입니다. `main` 같은 바뀌는 이름은 받지 않습니다. |
| `observed_fields` | 인물 데이터에서 확인한 값입니다. 공식 제도의 지원 자격을 뜻하지 않습니다. |
| `assumed_context` | 시험자가 추가한 상황입니다. 스마트폰이 없다는 시험 조건을 나이에서 추정하지 않고 이곳에 따로 적습니다. |
| `unknown_fields` | 확인하지 못한 속성 이름입니다. 같은 속성을 앞의 두 칸에 동시에 넣으면 오류입니다. |
| `guidance` | 시험할 안내문 또는 정책 문안의 식별자·판·원문·SHA-256·예시 여부입니다. |
| `question` | 인물에게 물을 문장입니다. |
| `jurisdiction`, `as_of` | 시험할 지역과 기준일(`YYYY-MM-DD`)입니다. |
| `reference_documents` | 근거 문서 식별자·제목·판·원문·해시·지역·시행 기간·검토 여부·예시 여부입니다. 기간 끝은 그날까지 유효하며, 끝이 없으면 `null`입니다. |
| `expected`, `forbidden` | 동작 식별자·구체적인 동작·근거 문서의 식별자 목록입니다. 존재하지 않는 문서를 참조하면 오류입니다. |

본문 해시는 공백·줄바꿈·유니코드를 바꾸지 않은 원문의 UTF-8 바이트로 계산합니다. `pp.scenario.text_sha256(text)`로 만들 수 있습니다. 안내문을 고칠 때는 판과 해시를 함께 갱신합니다. 기대·금지 동작의 근거는 인물의 서술이 아니라 해당 제도 문서에서 가져옵니다.

```bash
cd engine
../.venv/bin/python -m pp validate-scenario scenarios/examples/offline-help-v1.json
```

프로그램에서는 `pp.scenario.validate_scenario(card)`를 호출합니다. 잘못된 필수값·형식·해시·참조는 `ValueError`로 거절합니다. 추가 패키지나 모델 호출은 필요하지 않습니다. 내장 검사는 v1 스키마에서 사용하는 항목을 검사하며, 임의의 JSON Schema를 실행하는 범용 도구는 아닙니다.

형식이 맞아도 예시·임시 자료(`placeholder: true`), 미검토 근거(`review_status: "unreviewed"`), 지역 불일치, 기준일에 유효하지 않은 근거가 있으면 `status: "deferred"`와 사유를 돌려줍니다. `ready`는 기록된 근거를 평가에 사용할 수 있다는 뜻입니다. 응답의 합격이나 근거의 진위를 자동으로 보증하지 않습니다. 지역은 같은 문자열인지 비교하므로 전국 규정도 시험 지역에 맞게 적용 범위를 검토해 기록해야 합니다. CLI는 형식 오류에서 종료 코드 2를 내며, 형식이 맞는 보류 자료는 종료 코드 0과 `deferred`를 출력합니다. 자동 평가에서는 이 상태를 확인해야 합니다.

## 선택 영수증

정책 파이프라인의 새 패널 선택은 `runs/<id>/selection.json`을 만듭니다. 내보낸 결과의 `selection`에도 같은 기록이 들어갑니다. 과거 실행의 영수증은 소급해 만들지 않으며, 영수증이 없으면 내보낸 값도 `null`입니다.

- `data`에는 실제 선택에 사용한 인물 원본의 종류, 내용 해시(`panel_version`), 원본 저장소·revision·확인 상태를 남깁니다. 원본 revision을 모르면 `null`과 `unknown`을 그대로 남깁니다. 생활 여건을 추가한 조사 패널 버전은 실행 `meta`에서 함께 확인합니다.
- `requested_spec`과 `normalized_spec`에는 각각 모델이 낸 원래 요청과 지역 별칭 등을 정리한 조건을 남깁니다. 모르는 키·지역을 지워 조건을 넓히지 않습니다. 모델이 잘못된 조건을 내면 기존 재시도 정책에 따라 고치도록 요청하며, 끝까지 잘못되면 실행이 실패합니다.
- `representative`에는 선택 범위인 uuid 풀(전체이면 `null`), 가능한 인원, 요청·선택 건수, 각 층의 인원·배정 좌석, 시드·uuid 순서를 남깁니다. 시도×연령대×성별 비례 배분 뒤 각 층에서 시드를 둔 무작위 추출을 합니다. 요청한 풀에서 uuid가 하나라도 사라졌으면 모델 호출 전에 중단합니다.
- `affected.filter_groups`에는 속성 조건 묶음별 SQL 템플릿·바인딩 인자·전체 일치 수·반환 건수·상한·정렬을 남깁니다. 상한을 넘지 않으면 id 오름차순으로 그대로 반환하며 무작위 추출이 아닙니다. 넘으면 시드로 비복원 추출한 뒤 id순으로 정렬합니다. 여러 묶음은 번갈아 합쳐 중복을 빼고 최대 300명까지 담습니다.
- `affected.fts`에는 요청 검색어·실제 쓸 수 있는 검색어·순위를 남깁니다. 2글자 단어는 색인 대상 열에서 글자 그대로 부분 일치를 찾고 id순으로 정렬합니다. 3글자 이상은 FTS 관련도 순, 동점이면 id순입니다. 두 결과는 번갈아 합치고 중복을 없애며, 1글자 단어는 제외합니다. 의미 검색은 유사도 순이며 무작위 추출이 아닙니다. 의미 검색 동점 순서는 고정하지 않았다는 점과 DB에서 못 찾은 uuid도 남깁니다.
- 영향권은 세 검색 경로의 합집합에서 대표 패널을 뺀 뒤 권역·연령대에 번갈아 배정하고, 여러 경로에서 찾은 후보를 우선합니다. 동점과 배정 순서에는 시드를 둔 무작위 처리가 들어갑니다. 직업별 상한은 5명에서 시작해 인원이 모자랄 때 5명씩 늘립니다. `affected`에 이 방식·시드·후보 수·경로별 수·uuid·발견 경로를 남깁니다. 후보가 부족하면 실제 선택 건수가 요청보다 작을 수 있습니다.

영수증은 누가 어떤 조건과 순서로 선택됐는지 확인하는 자료입니다. 검색 결과는 단서에 맞는 확인 후보이며 실제 지원 자격이나 국민 대표성을 확정하지 않습니다. 같은 데이터·코드·시드에서 선택 순서를 비교할 수 있으며, 데이터나 의미 검색의 동점 순서가 달라지면 같은 선택을 보장하지 않습니다.

## 공청회 문안 전달 범위

공청회는 공백을 정리한 문안 앞부분을 최대 900자까지 받습니다. 초과하면 원문 899자와 줄임표 1자를 받습니다. 새 `hearing.json`의 `policy_truncated`, `shown_chars`, `total_chars`, `original_chars`, `policy_excerpt`와 같은 값이 `meta.json`의 `hearing_context`에도 남습니다. `shown_chars`는 줄임표를 포함한 전달 길이이며, `total_chars`는 공백을 정리한 전체 문안 길이입니다. `original_chars`는 공백 정리 전 원래 길이입니다.

절단된 결과에는 `context_note`가 붙고 공개 공청회 화면에도 표시됩니다. 잘린 조항의 예외가 발언에 없다는 이유만으로 그 인물이나 안내문의 문제라고 단정하지 않습니다. 과거 결과에 이 기록이 없으면 전달 범위를 확인할 수 없는 상태입니다.
