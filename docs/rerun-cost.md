# 같은 입력으로 이어 돌리기와 수정안 비교

## 입력이 바뀌면 새 폴더를 씁니다

`pp run`은 문안 전체(질문과 참고자료 같은 추가 항목 포함), 자료 버전, 인물 후보 UUID,
표본 수와 seed, 실제 모델과 서버 주소의 지문, 생성 설정, 프롬프트·판정 코드, 실행 한도를 묶어
SHA-256 `input_hash`를 `meta.json`에 적습니다. 인물별 반응에도 실제 프로필과 질문 지시문의
`input_hash`를 적습니다. 키와 서버 주소의 비밀값은 기록하지 않습니다.

같은 폴더에서 조건이 달라지면 `policy.json`이나 이전 결과를 바꾸기 전에 중단합니다.
지문이 없는 옛 결과도 자동으로 이어 쓰지 않습니다. 원문 실행을 보존하고 새 폴더를 지정합니다.

```bash
cd engine
PP_LLM_PROVIDER=mock PP_JEV_PROVIDER=mock python -m pp run policies/subway.json \
  --run-dir ../runs/subway-revised --n-rep 30 --n-aff 10 --n-jev 60 --n-alt 20 --allow-mock
```

`--force`는 바뀐 입력을 억지로 이어 쓰는 옵션이 아닙니다. 같은 입력의 단계를 다시 실행할 때만 씁니다.
웹 조사의 재시도도 문안·질문·선택지·인물 프로필·자료·모델·판정 코드가 같은지 확인한 뒤 답을 복사합니다.
새 지문은 결과 JSON의 `input_hash`에 담습니다. 옛 실행은 읽을 수 있지만 지문 없는 부분 응답은 재사용하지 않습니다.

## 같은 인물에게 원문과 수정안을 반복해서 묻습니다

```bash
PP_LLM_PROVIDER=mock PP_JEV_PROVIDER=mock python -m pp compare \
  ../runs/subway-original policies/subway.json --out ../runs/subway-comparison \
  --question '이 안내를 읽고 지원안에 찬성하십니까?' --repeats 3 --max-calls 3000
```

이 명령은 이전 실행의 `personas.json`에 저장된 UUID와 프로필을 그대로 씁니다. 자료를 다시 뽑지 않습니다.
원문과 수정안 모두 같은 명시적 질문으로 새로 묻습니다. 이전의 단일 응답을 비교 기준으로 섞지 않습니다.
현재 선택한 모델과 프롬프트를 양쪽에 같이 사용하므로 문안 수정 효과를 살펴보는 모드입니다.
반복 횟수는 2~10회입니다. 각 회차의 JSONL을 모두 남기며, 같은 명령을 다시 실행하면 같은 입력의 미완료 부분만 이어갑니다.

`comparison.json`에는 UUID별 원문·수정안 점수 목록, 평균 차이, 각 버전의 점수 범위와
회차별 찬성 점유율(`support > 0`)을 적습니다. `repeat_drift_pp`는 반복 회차의 가장 큰 점유율과
가장 작은 점유율 차이(%p)입니다. 이 수치는 실제 여론이나 정책 효과가 아닙니다.
문안 외 제목 등 여러 항목이 함께 바뀌면 원인을 분리할 수 없다는 경고도 적습니다.
모의 모델은 같은 입력에 같은 답을 내므로 흔들림이 0일 수 있습니다.

## 호출마다 한도를 확인합니다

`run`과 `compare`의 기본 한도는 다음과 같습니다. 비교의 모든 회차와 모든 역할이 하나의 한도를 나눠 씁니다.

| 옵션 | 기본값 | 뜻 |
|---|---:|---|
| `--max-calls` | 100000 | 실패와 재시도를 포함한 최대 호출 수입니다. |
| `--max-output-tokens` | 16384 | 문장 API에 보내는 출력 토큰 상한입니다. |
| `--max-retries` | 2 | 최초 호출 뒤 허용할 최대 재시도 수입니다. |
| `--max-concurrency` | 8 | 역할을 합친 동시 모델 호출 수입니다. |
| `--max-cost-usd` | 10 | 실행 전체의 달러 비용 상한입니다. |

인물 반응뿐 아니라 대상 선정, 판정, 쟁점, 가상 공청회, 요약, 계획서에도 적용합니다.
호출 전에 입력 바이트 길이를 기준으로 보수적으로 예상액을 예약합니다. 응답이 잘못된 JSON이더라도
공급자가 돌려준 usage를 기록합니다. 시간 초과나 usage 누락은 비용 불명으로 남기고 예약액을 보존합니다.
한도에 닿으면 예산 오류를 재시도하지 않고 멈춥니다. 이미 진행 중인 호출은 끝날 수 있습니다.

문장 API의 입력·출력 단가는 각각 `PP_LLM_INPUT_USD_PER_M`, `PP_LLM_OUTPUT_USD_PER_M`에 적습니다.
단위는 백만 토큰당 달러이며, 두 역할의 모델이 다르면 더 비싼 모델을 포괄하는 상한 단가를 적습니다.
로컬 모델이 청구하지 않으면 두 값 모두 `0`으로 명시합니다. 사용자 지정 판단 서버도
`PP_JEV_INPUT_USD_PER_M`, `PP_JEV_OUTPUT_USD_PER_M`으로 같은 방식으로 적습니다.
공식 판단 모델은 엔진에 기록된 단가를 사용하므로 운영자가 실제 계약 단가를 확인해야 합니다.
단가가 없으면 금액 제한이 있는 실행은 호출 전에 멈춥니다. 모의 호출만 자동으로 0원입니다.

CLI 구독 호출은 금액·출력 토큰을 서버에 강제할 수 없습니다. CLI를 쓰는 로컬 `run`·`compare`는
`--unknown-cost`를 명시해 금액을 모르는 호출 수 제한 모드로 실행할 수 있습니다.
이 경우 `cost_usd`는 `null`, `cost_status`는 `unknown`입니다. 출력 길이는 응답을 받은 뒤
토큰당 최대 4바이트 기준의 길이 제한으로 검사합니다. 정형 판단 API도 같은 사후 길이 검사를 합니다.
사후 검사는 이미 발생한 청구를 취소하지 않습니다. 토큰 상한을 지원하는 OpenAI 호환·EXAONE API는
요청에도 상한을 보냅니다. 공급자의 과금·토큰 계산과 단가를 완전히 통제할 수는 없으므로 공급자 한도도 함께 사용합니다.

`budget.json`과 `budget.attempts.jsonl`은 예약과 정산을 남깁니다. 중단 후 이어 돌려도 이전 사용량이 사라지지 않습니다.
같은 예산 파일을 두 프로세스가 동시에 실행하려 하면 중단합니다. 결과 메타의 `budget`에도 역할별 시도 내역을 담습니다.
`cost_status=unknown`이고 금액이 적혀 있으면 확정 청구액이 아니라 미정산 예약액이 포함된 값입니다.

웹 서비스는 `PP_MAX_CALLS`, `PP_MAX_OUTPUT_TOKENS`, `PP_MAX_RETRIES`, `PP_MAX_CONCURRENCY`,
`PP_MAX_COST_USD`로 같은 한도를 설정합니다. 일일 예산은 기존 `PP_DAILY_BUDGET_USD`와 함께 적용합니다.
심층 분석은 일일 장부에 최대 $0.50 또는 `PP_MAX_COST_USD` 중 작은 금액을 먼저 예약하고 그 금액을 실행 상한으로 씁니다.
실패·비용 불명일 때 이 예약을 돌려주지 않습니다. 서비스의 CLI 문장 모델은 금액을 제한할 수 없어 심층 분석을 중단합니다.
서비스 심층 분석에는 단가를 설정한 API 또는 모의 모델을 사용합니다.
