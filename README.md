# 백번 미리 묻다 (Policy Preview)

공개·가상 정책 문안으로 합성 인물에게 먼저 묻고, **실제로 누구를 찾아가 무엇을 물을지** 정하는 도구입니다.

> 실제 사람 응답 0명이며 합성 인물의 답은 실제 여론이 아닙니다. 이 도구는 여론조사나 공청회를 대신하지 않습니다. 발표 전 비공개 문안이나 개인정보는 입력하지 말고, 공개·가상 문안으로 먼저 만날 집단과 물어볼 질문을 고르는 데 쓰세요.

**저장소 주소** — README의 다른 곳은 모두 아래 `REPO_URL`을 가리킵니다.

```bash
REPO_URL=https://github.com/hosungseo/policy-preview-engine
```

## 1. 개요

정책 문안과 질문 하나를 넣으면, 공공 통계 분포로 만든 합성 인물(NVIDIA Nemotron-Personas-Korea)에게 같은 질문을 여러 방식으로 묻습니다. 그 결과로 다음을 보여 줍니다.

- **전체 응답과 흔들림 폭**: 문장을 바꾸거나 선택지 순서를 뒤집었을 때 답이 얼마나 흔들리는지 함께 잽니다. 흔들림이 크면 "이 문항의 숫자는 믿기 어렵습니다"라고 알립니다.
- **찾아갈 곳 카드**: 흔들림 폭을 넘어 전체와 뚜렷하게 다르게 답한 집단, 그 사람들이 많이 사는 곳, 만나기 좋은 장소를 카드로 보여 줍니다.
- **명단에 없는 사람**: 합성 명단에 없는 당사자(19세 미만, 외국인 주민 등)는 AI에게 묻지 않고, 직접 만나야 한다고 먼저 알립니다.
- **심층 분석(선택)**: 문장 모델이 일부 인물의 이유를 듣고 쟁점 묶기, 수정안 비교, 가상 공청회, 의견수렴 계획서 초안까지 만듭니다.

숫자는 코드가 계산하고, 판단은 확률을 답하는 판단 모델이, 문장은 문장 모델이 맡습니다. AI가 쓴 문장에는 "AI 작성" 표시가 붙습니다.

## 3. 작동 흐름

```
 정책 문안 + 질문 + 선택지
          │
          ▼
 ① 합성 패널에서 응답자 뽑기 ── 2만 명 묶음에서 시도 × 연령대 × 성별 비율대로(기본 3,000명)
          │
          ▼
 ② 판단 모델에게 묻기 ──────── 한 사람에게 세 판: 본 문항 · 대조 문장 · 선택지 순서 뒤집기
          │
          ▼
 ③ 코드가 집계 ─────────────── 전체 분포, 흔들림 폭, 집단별 차이(흔들림 폭을 넘는 것만)
          │
          ▼
 ④ 결과 화면 ───────────────── 찾아갈 곳 카드, 명단에 없는 사람, 먼저 물을 질문
          │
          ▼ (선택)
 ⑤ 심층 분석 ───────────────── 대표·영향권 인물의 이유 → 쟁점 묶기 → 수정안 비교 → 가상 공청회 → 계획서 초안
```

| 폴더 | 내용 |
|---|---|
| `engine/pp/` | 분석 엔진(인물 고르기, 판단·문장 모델 호출, 집계, 계획서) |
| `engine/ppservice/` | 웹 서비스(FastAPI). 로그인, 조사 실행·재시도, 결과 API |
| `engine/scripts/` | 자료 만들기·평가 스크립트. 패널 묶음은 `build_panel_from_nemotron.py` |
| `engine/policies/` | 예시 정책 문안(입법예고 원문 2건, 정책 요약 1건, 가상 정책안 2건) |
| `engine/series/` | 부동산 대책 흐름 예시의 입력(보도자료 발췌, 공공 통계 요약) |
| `web/` | Next.js 정적 화면. `web/public/runs/`·`web/public/series/`는 미리 실행한 예시 결과 |

## 4. 빠른 시작

준비물: Python 3.12, Node.js 24, 약 3GB 디스크(합성 인물 원본 내려받기).

### 4-0. 내려받기

```bash
git clone "$REPO_URL" policy-preview-engine   # REPO_URL은 맨 위 「저장소 주소」에 정의
cd policy-preview-engine
```

### 4-1. `.env` 설정

```bash
cp .env.example .env
chmod 600 .env
# 키 없이 시험할 때는 비워 둡니다. 실제 모델을 쓸 때만 키를 넣습니다.
```

`.env`는 git에 올리지 않습니다(`.gitignore`에 들어 있습니다).

### 4-2. 설치

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r engine/requirements.txt -r engine/requirements-service.txt
(cd web && npm ci && npm run build)          # 화면(web/out)을 만듭니다
```

### 4-3. 합성 인물 패널 만들기

```bash
cd engine
../.venv/bin/python scripts/build_panel_from_nemotron.py
cd ..
```

- Hugging Face에서 `nvidia/Nemotron-Personas-Korea`(공개, 로그인 불필요, parquet 약 2GB)를 `data/nemotron-personas-korea/`로 받습니다.
- 100만 명 가운데 시도 × 연령대 × 성별 비율대로 2만 명을 뽑아 `engine/ppservice/data/panel-20k.jsonl.gz`를 만듭니다. 같은 `--seed`면 같은 패널이 나옵니다.
- 이미 받은 parquet가 있으면 `--parquet-dir 폴더`로 넘깁니다.
- `--persona-db`를 붙이면 100만 명 전체를 SQLite(전문 검색 색인 포함, 약 10GB)로도 만듭니다. 정책 전체를 깊게 돌리는 `python -m pp run`과 `scripts/build_roster_1m.py`(찾아갈 곳의 시군구 인원표)가 이 DB를 씁니다.

### 4-4. 키 없이 시험하기 (`PP_JEV_PROVIDER=mock`)

```bash
scripts/serve-profile.sh mock                 # PP_JEV_PROVIDER=mock, PP_LLM_PROVIDER=mock으로 서버 실행
# 다른 터미널에서 접속 코드를 만듭니다(한 번만 보여 줍니다)
(cd engine && ../.venv/bin/python -m ppservice user add me@example.com)
```

http://127.0.0.1:8800/review/ 에서 이메일과 접속 코드로 들어갑니다. 내 컴퓨터에서만 쓸 때는 `PP_DEMO_LOGIN=1 scripts/serve-profile.sh mock`으로 접속 코드 없이 들어갈 수도 있습니다(다른 사람이 접속할 수 있는 서버에서는 켜지 마세요).

mock은 외부로 아무것도 보내지 않고, 정해진 규칙으로 자리 채움 답을 만듭니다. 화면 흐름을 확인하는 용도이며 결과 숫자에는 뜻이 없습니다.

엔진 테스트도 키 없이 돌립니다.

```bash
cd engine
PP_JEV_PROVIDER=mock PP_LLM_PROVIDER=mock ../.venv/bin/python -m pytest
```

서비스 테스트 일부(`needs_panel` 표시, 21개)는 4-3의 패널 묶음이 있어야 돌아갑니다. 묶음이 없으면 "2만 명 패널 묶음 없음" 사유로 건너뜁니다.

## 5. 판단 모델 선택

판단 모델은 정해 둔 선택지마다 확률을 답하는 모델입니다. `PP_JEV_PROVIDER`로 고릅니다. 키는 고른 공급자의 주소로만 보냅니다.

| 선택 | 설정 | 보내는 곳 |
|---|---|---|
| Jev (TypeSafe) | `PP_JEV_PROVIDER=api`, `TYPESAFE_API_KEY` | `https://api.typesafe.ai/v1/systemone` |
| 업스테이지 Solar Decide | `PP_JEV_PROVIDER=upstage`, `UPSTAGE_API_KEY` (모델 기본값 `solar-decide`) | `https://api.upstage.ai/v1/systemone` (기본, 글로벌) |
| 국내 처리: 업스테이지 한국 리전(비공개 베타, 접근 신청 필요) | 위 설정에 `PP_UPSTAGE_REGION=kr`을 더하거나, 안내받은 기본 주소를 `UPSTAGE_BASE_URL`에 넣음 | `https://kr.api.upstage.ai/v1/systemone` — 경로는 승인 후 안내 기준으로 확인 |
| 로컬 판단 모델 | `PP_JEV_PROVIDER=api`, `PP_JEV_URL=http://127.0.0.1:11434/v1/systemone`, `PP_JEV_MODEL=tev1:4b` 등 | 내 컴퓨터(외부 전송 없음) |
| 시험 | `PP_JEV_PROVIDER=mock` | 없음 |

- **국내 처리**: 업스테이지 한국 리전(`kr.api.upstage.ai`)은 비공개 베타이며 **접근 신청이 필요합니다.** 경로는 승인 후 안내 기준으로 확인하세요.
  - 주소를 고르는 순서: `UPSTAGE_BASE_URL` → `PP_UPSTAGE_REGION` → 기본값(글로벌 `https://api.upstage.ai/v1`). 요청은 고른 기본 주소 뒤에 `/systemone`을 붙여 보냅니다. 끝의 `/`는 떼고 붙입니다.
  - `PP_UPSTAGE_REGION`은 비우거나 `global`, `kr`만 받습니다. 다른 값이면 호출하기 전에 오류로 멈춥니다.
  - `UPSTAGE_BASE_URL`은 `https://` 주소만 받습니다. 업스테이지 키가 그 주소로 가므로 안내받은 주소만 넣으세요.
  - 업스테이지 키가 다른 주소로 새지 않도록 `PP_JEV_URL`은 업스테이지 설정에 쓰이지 않습니다.
- **로컬**: Jev와 같은 형식으로 답하는 로컬 서버를 `PP_JEV_URL`로 연결합니다. 이때 TypeSafe 키는 보내지 않고, 그 서버가 키를 요구하면 `PP_JEV_API_KEY`만 보냅니다.

문장 모델(심층 분석의 이유·쟁점·공청회·계획서 문장)은 `PP_LLM_PROVIDER`로 고릅니다.

| 선택 | 설정 |
|---|---|
| `cli` (기본) | 내 컴퓨터의 `claude -p` 명령을 부릅니다 |
| `openai` | OpenAI 호환 API. `PP_LLM_BASE_URL`, `PP_LLM_MODEL`, 필요하면 `PP_LLM_API_KEY`. 로컬 서버(예: Ollama `http://127.0.0.1:11434/v1`)도 됩니다 |
| `exaone` | LG EXAONE. `EXAONE_API_KEY`와 `PP_EXAONE_LOCAL_ONLY=1`이 필요하고, 로컬 주소에서만 서버를 엽니다. 이용 조건(비상업)을 직접 확인하세요 |
| `mock` | 자리 채움 문장(외부 전송 없음) |

자주 쓰는 조합은 `scripts/serve-profile.sh`로 한 번에 켭니다.

```bash
scripts/serve-profile.sh global   # 문장: Claude(cli) · 판단: Jev
scripts/serve-profile.sh korean   # 문장: EXAONE · 판단: Solar Decide
scripts/serve-profile.sh local    # 문장: 로컬 OpenAI 호환 모델 · 판단: 로컬 판단 모델(기본 Ollama 주소)
scripts/serve-profile.sh mock     # 키 없음, 모델 호출 없음
```

화면에 지금 쓰는 모델 구성이 표시됩니다.

## 6. 비용 예시

현재 엔진은 모든 역할과 재시도를 합쳐 호출 수·출력 길이·재시도·동시 실행·총비용을 제한합니다.
입력이 바뀐 결과 이어쓰기도 차단하며, `pp compare`로 같은 인물에게 원문과 수정안을 반복해서 물을 수 있습니다.
옵션과 0원 예시는 [재실행·수정안 비교·비용 제한 안내](docs/rerun-cost.md)에 있습니다.
문장 API는 단가를 명시해야 금액 제한을 사용할 수 있습니다. CLI 구독 호출은 로컬 명령의 `--unknown-cost` 모드에서만 지원합니다.

아래는 개발 중 2026년 11월 10일에 잰 기록입니다. 같은 입법예고 문안(「공공기관의 정보공개에 관한 법률 일부개정법률안」 이유·주요내용 앞 1,500자), 같은 문항(찬성 / 반대 / 잘 모르겠다), 같은 합성 인물 300명을 세 구성으로 돌렸습니다. 사람마다 본 문항·대조 문장·선택지 순서 뒤집기 세 판을 물어 판단 모델 호출은 900회입니다.

| 구성 | 판단 모델 | 문장 모델 | 심층 분석에서 들은 사람 | 걸린 시간(심층 분석) | 비용 |
|---|---|---|---|---|---|
| 해외 | TypeSafe Jev | Claude | 400명(대표 300 + 영향권 100) | 13분 | 약 $0.13 |
| 국산 | Upstage Solar Decide | LG EXAONE k-exaone_v2.5 | 29명 | 38분 | 약 $0.11 |
| 로컬 | tev1:4b (Ollama) | Gemma 4 26B | 10명 | 25분 | 0원(외부 전송 없음) |

- 구성마다 심층 분석에서 들은 사람 수가 달라 비용·시간을 그대로 견주면 안 됩니다.
- 같은 날 Solar Decide는 분당 100건·5만 토큰 한도가 있어 병렬 호출을 16으로 올리자 429 오류가 났습니다. 코드는 업스테이지가 알려 주는 재시도 시각까지 기다립니다.
- 단가는 바뀔 수 있으니 각 회사의 최신 안내를 확인하세요. 코드가 비용을 계산할 때 쓰는 입력 단가는 `engine/pp/jev.py`에 있습니다.

## 7. 한계

- **합성 인물이며 실제 여론이 아닙니다.** 인물은 공공 통계 분포로 만든 합성 자료이고, 답은 AI 모델이 그 인물이라고 가정하고 낸 추정입니다.
- **명단에 없는 사람**: 합성 인물은 19세 이상 국민만 있습니다. 19세 미만, 외국인 주민, 단체·업계의 조직된 의견은 들을 수 없습니다. 기본 인물에는 소득 정보가 없습니다. 생활 여건 애드온의 가구 연소득은 공공 통계로 배정한 가정이고, '5년 뒤 보기'의 개인 근로·사업소득도 별도 모의 값입니다.
- **가구 통계의 근사**: 가구 연소득·부채·자동차·순자산은 가구 기준 통계를 사람 단위 패널에 맞춰 배정합니다. 가구 연결키와 정확한 가구원 수가 없어 가구 가중치를 개인 가중치로 바꿀 수 없습니다. 임의의 가구를 만들어 추가 가정을 얹는 대신 기존 근사를 유지하며, 배정 진단의 `finance_unit`과 `limitations`에 이를 기록합니다. 사람 수로 계산한 분포는 공식 가구 비율이나 국민 개인 비율로 해석할 수 없습니다. 가구주 연령도 추정이며 맞벌이 배정에는 본인 연령을 사용합니다.
- **가구 이름은 가구 구성입니다**: 집계의 '배우자 없이 자녀와 거주'(이전 이름 '한부모·자녀')와 찾아갈 곳의 '배우자 없이 자녀와 사는 사람'은 함께 사는 사람으로 나눈 이름입니다. 원자료의 '자녀와 거주 (한부모)'에는 다 큰 자녀와 사는 어르신도 들어 있습니다(2만 명 패널의 648명 중 284명, 44%가 60세 이상). 한부모가족 같은 지원 대상인지는 자녀 나이·양육·소득 같은 제도 기준으로 따로 정해지므로, 이 이름으로 판단하지 않습니다. 이전에 저장한 예시 결과도 화면에서는 새 이름으로 보입니다.
- **표본 편향**: 2만 명 묶음은 시도 × 연령대 × 성별 비율만 맞춥니다. 학력·직업·가구 같은 다른 속성은 원자료 분포를 따르며, 시군구 단위로 내려가면 인원이 적습니다. AI 응답은 합의를 부풀리거나 '중도'로 몰리기 쉽습니다.
- **교차 칸이 적으면 집단 차이로 단정하지 않습니다**: 나이·지역 합계가 공식 통계와 맞아도 직업 × 학력 같은 조합까지 현실과 같다고 보지 않습니다. 몇 명뿐인 칸(예: 시군구 × 직업)의 점수 차이를 그 속성 때문이라고 적지 않습니다. 화면은 흔들림 폭을 넘는 차이만 찾아갈 후보로 보여 주며, 작은 칸의 숫자는 찾아갈 곳을 고르는 근거로 크게 쓰지 않습니다.
- **모델마다 답이 다릅니다**: 위 비용 예시의 같은 문항에서 찬성 / 반대 / 모름은 해외 65 / 5 / 30, 국산 63 / 3 / 34, 로컬 84 / 4 / 12였습니다. 해외·국산 구성은 순서 뒤집기 흔들림이 7%p를 넘어 경고가 떴습니다.
- **정확도**: 통계청 「2024 사회조사」 문항을 같은 합성 인물에게 묻고 공식 분포(20세 이상, 연령 가중)와 비교했습니다(2026-11-10). 결과를 보기 전에 고른 처음 보는 5문항에서 평균 절대 차이는 Jev 11.0%p, Solar Decide 10.7%p, tev1:4b 10.3%p였습니다. 기록은 `engine/ppservice/data/persona-accuracy/holdout-2026-11-10.json`에 있습니다. 인물 설명을 더 붙인다고 오차가 고르게 줄지는 않습니다. 아래 [참고 글](https://note.com/gtminami/n/nc7c8fce9b605)이 인용한 세 편도 같은 방향입니다.
  - Morocho 외(2026), [Assessing the Reliability of Persona-Conditioned LLMs as Synthetic Survey Respondents](https://arxiv.org/abs/2602.18462): 미국 세계가치관조사 응답 7만여 건에서 인물 속성을 붙여도 전체 일치도가 뚜렷이 오르지 않았고, 일부 문항과 인원이 적은 집단에서 오차가 커졌습니다.
  - Jia 외(2026), [When Can Digital Personas Reliably Approximate Human Survey Findings?](https://arxiv.org/abs/2605.10659): 네덜란드 LISS 패널에서 응답 분포는 가까워졌지만 한 사람의 답과 응답 구조는 잘 맞히지 못했습니다. 그 사람이 예전에 실제로 한 응답을 찾아 붙인 방식이 가장 나았습니다.
  - Pourtaheri·Zareei(2026), [Behavioral History Outperforms Descriptions of the Person for LLM Synthetic Personas](https://arxiv.org/abs/2610.03998): 미국 성인 845명 패널에서 평균은 사람과 비슷했지만, 인물 설명만 주면 사람 사이 차이의 53~67%만 나왔습니다. 그 사람의 과거 응답을 주자 사람 수준에 가까워졌습니다.
- **소수의 세부 이해관계에 약합니다**: 같은 입법예고에 실제로 제출된 공개 의견과 견주어 보니, 큰 방향의 쟁점은 짚었지만 절차 조항처럼 제도를 직접 쓰는 소수의 세부 이해관계는 세 구성 모두 놓쳤습니다.

## 8. 결과를 읽을 때 주의

- **합성 인물 N명은 N명이 답한 조사가 아닙니다.** 화면의 "3,000명"은 판단 모델이 합성 인물 3,000명 각각이라고 가정하고 낸 추정의 개수입니다. 실제 사람 3,000명에게 물은 결과가 아닙니다.
- **비율도 실제 비율이 아닙니다.** 합성 인물 100명 중 70명이 찬성해도 실제 찬성률 70%가 아닙니다. 숫자는 집단끼리 견주어 먼저 찾아갈 곳을 고르는 데 씁니다.
- **한 사람은 한 명으로 셉니다.** 한 사람에 직업·여가·가족 같은 여러 설명과 공공 통계로 배정한 생활 여건 줄이 붙어 있어도 사람 수는 하나입니다. 설명마다 따로 세면 같은 사람을 여러 번 세게 됩니다.
- **대표 패널과 영향권 패널은 따로 읽습니다.** 대표 패널은 시도 × 연령대 × 성별 인구 비율대로 뽑은 사람이고, 영향권 패널은 정책이 직접 닿는 조건(직업, 낱말, 의미 검색)으로 골라 넣은 사람입니다. 목적이 다르므로 두 패널을 합쳐 비율을 내지 않습니다. 영향권 패널의 수치를 전체 국민의 비율로 읽지 마세요. 전체 응답 분포는 대표 패널에서만 냅니다.

## 9. 데이터를 다룰 때 주의

패널 묶음이나 생활 여건 파일(공공 통계로 배정한 가구 소득·건강 같은 가정, `engine/pp/life_context.py`)을 직접 집계하거나 다른 분석에 쓸 때 지킬 것입니다.

- **'불명', '비해당', '없음'은 서로 다른 값입니다.** 불명은 알 수 없는 값, 비해당은 그 사람에게 해당하지 않는 항목(예: 일하지 않는 사람의 출퇴근 수단), 없음은 확인된 '아니오'입니다. 비해당이나 불명을 0이나 '없음'으로 세지 마세요. 비율을 낼 때는 분모를 해당하는 사람으로 좁힙니다(예: 고혈압 진단 경험률은 30세 이상만). 생활 여건 파일에 항목이 빠져 있다고 '없음'은 아닙니다. 인물 설명과 어긋날까 봐 일부러 뺀 주제는 `skipped`에 적혀 있습니다.
- **새 배정 코드의 값 형식**: 누락 값은 JSON `null`과 `value_status.<항목> = "unknown"`, 비해당은 `null`과 `"not_applicable"`로 남깁니다(30세 미만 고혈압·당뇨, 무직의 출퇴근). `false`는 해당하는 항목에서 뽑힌 '없음'입니다. 공표되지 않은 소득 구간은 `null`로 보존하고, 불완전한 분포는 레이크 목표에서 제외합니다. 전체 소득 분포가 없으면 배정을 중단합니다. 이 변경은 `life-context-values-v3` 진단값으로 식별합니다. 기존 생활 여건 파일을 자동 변환하거나 재생성하지 않았으므로 이전 파일의 0·false를 새 의미로 해석하면 안 됩니다.
- **세대 단위 값과 개인 단위 값을 더하지 않습니다.** 가구 연소득·가구 부채·자동차·주거 점유·순자산은 그 사람이 사는 가구의 값이고, 서비스의 '5년 뒤 보기'에 붙는 개인 근로·사업소득은 본인의 값입니다. 둘을 더하거나 같은 단위로 견주지 않습니다. 가구의 값을 사람마다 붙였으므로, 사람 수로 낸 비율은 공식 통계의 가구 비율과 뜻이 다릅니다.
- **디지털 항목은 정보 찾기 설문의 대리값입니다.** 생활 여건의 '인터넷·스마트폰으로 필요한 정보를 잘 찾음 / 찾기 어려워함'은 스마트폰 과의존 실태조사의 '온라인에서 필요한 것을 찾을 수 있다' 문항 분포로 배정한 값입니다. 70세 이상은 디지털정보격차 실태조사의 역량 지수로 낮춰 맞춥니다(`engine/pp/life_context.py`의 `assign_digital`). 스마트폰이 있거나 정보를 잘 찾는다고 서류 제출·앱 신청 같은 절차를 해낼 수 있다는 뜻은 아닙니다. 안내문 시험에 절차 조건이 필요하면 시험 조건으로 따로 적고(예: '스마트폰 없음', '파일 첨부 못 함'), 나이로 채우지 않습니다. 모르는 조건은 '모름'으로 두고 '있음'으로 채우지 않습니다. 찾아갈 곳 카드와 조사 결과에는 이 뜻을 함께 적고, 절차 능력을 묻는 문항은 문항 점검(`procedure_ability`)에서 경고합니다.
- **소득 구간으로 금액·수급·상환 능력을 계산하지 않습니다.** 가구 연소득은 가계금융복지조사 분포로 배정한 구간(예: 1천만~3천만 원)이며 조건을 나누는 데만 씁니다. 구간의 가운데 값을 그 사람의 금액으로 넣어 지원 금액, 수급 자격, 대출 상환 능력을 계산하지 않습니다. 코드의 구간 가운데 값(`INCOME_MIDPOINT`)은 공표 평균과 맞추는 보정에만 쓰고, 다른 곳에서 쓰면 테스트가 실패합니다. 기초생활보장 수급 표시도 통계로 배정한 가정입니다. 금액·자격·상환을 묻는 문항은 문항 점검(`amount_calc`)에서 경고합니다. '5년 뒤 보기'의 대상 규칙 보기는 별도 모의 개인 소득 금액으로만 판정하고, 금액이 없으면 판정하지 않습니다.
- **열 이름만 보고 뜻을 짐작하지 않습니다.** 이름이 같아도 표마다 정의가 다를 수 있습니다(예: 월 소득 구간이 가구 소득인지 개인 소득인지). 합성 인물은 Hugging Face 데이터 카드, 공공 통계는 각 파일의 `sources`·`sources_detail`에 적힌 표 ID로 원래 정의를 확인합니다.
- **결과와 함께 데이터 버전과 인물 uuid를 기록합니다.** 웹 서비스는 실행마다 패널 버전(`panel_version`: 패널 묶음 내용의 해시, 붙인 생활 여건 항목과 그 파일의 해시)과 인물별 uuid 응답을 남깁니다. 새 패널 생성 코드는 다운로드할 HF revision을 커밋 SHA로 확정해 같은 SHA로 내려받고, 패널·인물 DB 옆 `<파일명>.meta.json`에 `source_revision`과 seed를 기록합니다. `--revision`으로 내려받을 버전을 지정할 수 있습니다. 로컬 `--parquet-dir`은 원본을 검증할 수 없어 revision을 생략하면 `null`, 커밋 SHA를 주면 `user_supplied`로 표시합니다. 새 심층 분석 결과 meta와 계획서에도 패널 해시·원본 revision을 남깁니다. 과거 파일·실행의 revision은 소급해 추측하지 않으며 `null`/미기록입니다. 결과를 옮길 때 메타데이터 파일·uuid·seed도 함께 옮기세요.
- **인물 선택 조건을 조용히 빼지 않습니다.** 지원하지 않는 키·지역·성별 값, 빈 조건, 거꾸로 적힌 연령 범위는 오류로 처리합니다. 새 패널 선택은 `runs/<id>/selection.json`에 요청 조건과 실제 조건, 정렬·추출 방식, 건수, uuid 목록, 데이터 revision을 남깁니다. 대표 패널은 시드를 둔 층화 무작위 추출이며, 영향권은 속성·단어·의미 검색 후보를 합쳐 고릅니다. 검색 순위가 무작위인지도 영수증에서 구분합니다.
- **시험 카드에 안내문 판과 근거를 고정합니다.** [공개 규격과 사용법](docs/scenarios.md), [JSON 스키마](engine/scenarios/schema-v1.json), [가상 예시](engine/scenarios/examples/offline-help-v1.json)를 제공합니다. 인물 uuid·원본 revision, 데이터에서 확인한 값·시험자가 추가한 가정·미상 값, 안내문 판·본문 해시, 질문·기대 동작·금지 동작·근거를 한 파일에 담습니다. `python -m pp validate-scenario scenarios/examples/offline-help-v1.json`으로 모델 호출 없이 검사합니다. 예시·미검토·지역 불일치·기준일 밖 근거는 ‘판정 보류’입니다.
- **단어만으로 양육 여부를 확정하지 않습니다.** 찾아갈 곳의 보육 관련 서술은 ‘영유아·보육 관련 언급 인물(확인 후보)’로 표시합니다. 교사·근무·인근 거주·부정 표현은 걸러도 문맥 검사에 한계가 있으므로 실제 가구 구성은 따로 확인합니다.
- **가상 공청회에 전달한 문안 범위를 기록합니다.** 공백을 정리한 정책문이 900자를 넘으면 앞 899자와 줄임표를 전달합니다. 새 `hearing.json`과 `meta.json`의 `hearing_context`에 절단 여부·전달 길이·전체 길이·실제 전달 문안을 기록하고, 공청회 화면에 잘렸다는 안내를 표시합니다. 잘린 뒷조항이 발언에 반영됐다고 해석하지 않습니다.

참고: 南翔伍, [「NVIDIAの「100万人の合成ペルソナ」をどう使う？」](https://note.com/gtminami/n/nc7c8fce9b605)(note, 2026년 11월). 일본판 Nemotron 합성 인물을 쓸 때의 주의점(인물 수와 응답자 수의 차이, 불명·비해당·없음 구분, uuid와 데이터 버전 기록)을 정리한 글입니다.
